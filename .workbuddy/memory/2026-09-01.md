## UE 偏移表 Bug 修复（UEOffsets.cpp + UEGameProfile.cpp + UECandidateAnalysis.cpp）

核对答案卷后锁定并修复三个 Bug：

**Bug 1（UE4.2x NumElements 偏移）**：`UEOffsets.cpp` 中 UE4_20 / UE4_23_24 / UE5_00_02 三处均设为 `(sizeof(void*)*2) + sizeof(int32) = 0x14`（UE5 布局），UE4.2x 应为 `sizeof(void*) + sizeof(int32)*3 = 0x10`。已改为 `0x10` 并加注释说明。

**Bug 2（GetGUObjectArrayPtr 只验 ID=0）**：`UEGameProfile.cpp` 里原验证逻辑只查 slot 0 是否为 `/Script/CoreUObject`，但 UE4.2x 的 slot 0 是保留空槽，真对象从 slot 1 起。改为扫描前 8 个槽位，对每个有效槽验证 name 解析，统计锚点命中数（`anchorHits > 0` 即通过）。新增 lambda `verifyCandidate()`，复用 chunk0 指针，提取了 `stableItemSize` 变量。

**Bug 3（sampleGnames 偏移错位）**：`UECandidateAnalysis.cpp` 的 `anchorOffsets` 传入的是字节偏移 `{0,2,4,6,...}`，但 `DecodeNameAt` 内部会乘 `layout.stride`，导致 UE4.2x (stride=2) 时 byte_offset 2 变成 entry 4，跳过 id=1（"ByteProperty"）。修复：在调用 `ValidateNameCandidate` 前将 byte offset ÷ layout[0].stride 转成 unit offset。

## GetGUObjectArrayPtr 被 isPtrWritable 限制持续失败 修复

用户反馈"通用方式搜索 GUObject 持续失败"，怀疑代码限制问题。对比 `UEGameProfile未改动代码.cpp.bak`（原始）与 `UEGameProfile.cpp`（当前）发现三处过度限制被引入：

| L932/1124 | `isPtrReadable(chunk0)` | `isPtrWritable(chunk0, ...)` | **chunk 数组指针只读就挂掉** |
